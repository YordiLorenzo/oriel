Fast, cheap computer use for Windows.

oriel is an MCP server that lets your AI assistant use the apps on your own Windows PC. It reads each window as text, through the accessibility tree, instead of sending the model screenshots.

Text, not screenshots

Most computer-use agents work from screenshots. Every step sends the model a picture, clicks land on a guessed pixel, and each click takes over the pointer you are using. Windows already describes every window as a tree of named controls, for screen readers such as Narrator. oriel reads that tree, gives it to the assistant as text, acts on the controls directly, and answers each action with what changed.

How it compares

Three ways to let an assistant use a Windows PC: oriel, Cua Driver, and agents that work from screenshots.

oriel Cua Driver Screenshot-based agents
How it sees a window The accessibility tree, as text The accessibility tree, as text, with screenshots on request Screenshots, read by the model
How it acts Accessibility actions on the control; real keys and mouse only for keys, click and drag Accessibility actions on element tokens, plus keyboard and mouse tools Mouse clicks at pixel positions, and typing
What an action changed In the same reply, control by control Read the window again A new screenshot, compared by eye
Canvases and games screenshot, click and drag, or oriel-vnc Screenshots and mouse What they are built for

Choose a screenshot-based agent if most of the work is in games, canvases or remote desktops, where there is no accessibility tree. Cua Driver is close to oriel per action and completed a few more benchmark tasks. oriel is for assistants working in everyday Windows apps, where it finishes tasks in less time and for less money.

Refs and change reports

Every action says what changed

tree lists a window's named and actionable controls, one per line, each with a ref such as kqm17. The assistant acts on a ref directly, without searching again. Every action replies with what changed in the window, so the assistant rarely has to look twice.

  • oriel waits until the app has stopped reacting, using the window's own accessibility events rather than fixed sleeps, so the report shows the finished result.
  • An element keeps its ref while it exists, and a ref never moves to another element, so an old ref can't hit the wrong control.
  • A name that matches nothing comes back with the closest names, so the assistant can try again without a search.

Background actions

In the background, so you can keep working

invoke, set, select and scroll act through UI Automation. They don't take keyboard focus or move the mouse, so you can keep working while the assistant does.

  • keys, click and drag send real input, for things with no accessibility action: spreadsheet cells, canvases, drawing.
  • They bring the window to the front first, check it is the right one, and wait for a pause in your own typing and mouse use.
  • An action takes 5 to 20 ms and reading a window 20 to 60 ms, measured from another computer on the same network.

Safety

Kept away from passwords, sign-in and terminals

oriel works on your real desktop, so it is careful by default. In a window it is allowed to use, the assistant can do what you can; an allow-list keeps it to the apps a task needs.

  • Password fields can't be filled, read or typed into.
  • The lock screen, sign-in and UAC prompts, Windows credential dialogs and common password managers are off limits.
  • No shell by default: no tool runs commands or reads or writes files, launch refuses command interpreters, and open terminals are off limits.
  • The daemon listens on loopback only, and every connection proves it holds your per-user key, so only your own clients can use it. The key itself is never sent.

One file

One 180 KB exe, on the PC or over SSH

oriel.exe has no dependencies: it runs on the .NET Framework 4.8 that Windows includes, so there is nothing else to install. Use it on the PC itself, or from a Mac or Linux machine over SSH.

  • No admin rights, no service, no driver.
  • An SSH session has no desktop, so over SSH oriel mcp passes each call to oriel's daemon in your desktop session, and starts the daemon if it isn't running.
  • No SDK needed to build it yourself: the C# compiler that ships with Windows is enough.

Launch, wait and batch

Fewer model turns per task

launch replies with the new window's tree. wait reacts to the window's own events instead of polling. batch runs a sequence of steps in one call, and its report covers the whole batch. In WindowsAgentArena round 9, tasks took 21.8 turns with oriel against 27.0 with Cua Driver.

  • In Claude Code the tools load up front instead of behind a tool search, which saves a turn at the start of a session.
  • screenshot shows one window, for canvases, charts and games, and screenshot=true on an action adds a picture of the result without an extra call.

What it works with

oriel is built on Windows UI Automation, the interface Narrator uses. Anything that exposes it can be read and acted on.

Windows

  • Windows 11: tested
  • Windows 10, version 1903 or later
  • The .NET Framework 4.8, which Windows includes

Not yet: Windows 10 isn't tested. On a locked PC, reading and element actions keep working, but keys, focus, click and drag are refused, and Windows suspends Store apps such as Calculator and Settings.

Apps

  • Anything that exposes UI Automation: most desktop apps (Win32, WPF, WinForms), Store apps, and web pages in browsers
  • Chromium browsers and Electron apps, through their accessibility tree
  • Exercised in WindowsAgentArena: Chrome, Edge, File Explorer, LibreOffice Calc and Writer, VS Code, VLC, Settings, Paint, Clock, Calculator and Notepad

Not yet: canvases and games have no accessibility tree, so screenshot shows them and click and drag act on them. Apps running as administrator need an oriel that also runs as administrator.

MCP clients

  • Any client that starts a stdio MCP server
  • Claude Code: most of the testing
  • Codex, Claude Desktop, Cursor and VS Code: configs that follow their documented formats

Not yet: testing with clients other than Claude Code.

Other computers

  • macOS, Linux, or anything else with a VNC server, through oriel-vnc, the second MCP server in the repo
  • Screenshots scaled for the model, clicks in screenshot coordinates, keys, typing and a zoom for small text
  • Runs next to the assistant; nothing is installed on those machines

Pixels, not text: on Windows apps, oriel.exe is faster and cheaper. oriel-vnc is for what the accessibility tree can't reach.

Set up in three steps

oriel is a stdio MCP server: your assistant starts oriel.exe mcp and talks to it. Install it once for your Windows account, with no admin rights, then add it to your MCP client.

  1. Download oriel.exe

    Get it from the latest release. To check the file, compare Get-FileHash .\oriel.exe with the release's SHA256SUMS.

    Download oriel.exe

  2. Install it

    In PowerShell, in the download folder:

    .\oriel.exe install

    It copies oriel to %LOCALAPPDATA%\Programs\oriel and starts it. Add --autostart to start it at sign-in.

    0.1.0 isn't code-signed yet, so SmartScreen may show “Windows protected your PC”. Click:

    More info → Run anyway

  3. Add it to Claude Code

    In the same PowerShell window, which fills in the path for you:

    claude mcp add --scope user oriel -- "$env:LOCALAPPDATA\Programs\oriel\oriel.exe" mcp

    Then ask Claude “Which windows are open?” It answers through oriel's windows tool.

Other MCP clients

Every client needs the same two things: the full path to oriel.exe as the command, and mcp as the argument. Replace <you> with your Windows user name, or paste the path install printed. Restart the client after editing its file. Only Claude Code has been tested; these follow each client's documented format.

Codex %USERPROFILE%\.codex\config.toml

[mcp_servers.oriel]
command = 'C:\Users\<you>\AppData\Local\Programs\oriel\oriel.exe'
args = ["mcp"]

Claude Desktop, Cursor claude_desktop_config.json, .cursor\mcp.json

{
  "mcpServers": {
    "oriel": {
      "command": "C:\\Users\\<you>\\AppData\\Local\\Programs\\oriel\\oriel.exe",
      "args": ["mcp"]
    }
  }
}

VS Code .vscode\mcp.json

{
  "servers": {
    "oriel": {
      "type": "stdio",
      "command": "C:\\Users\\<you>\\AppData\\Local\\Programs\\oriel\\oriel.exe",
      "args": ["mcp"]
    }
  }
}

From a Mac or Linux machine

claude mcp add --scope user oriel -- ssh my-windows-pc 'C:\Users\<you>\AppData\Local\Programs\oriel\oriel.exe' mcp

The PC needs OpenSSH Server with key login. oriel passes each call to its daemon in your desktop session.

oriel-vnc, any desktop over VNC ~/.config/oriel-vnc/hosts.json

claude mcp add --scope user oriel-vnc -- uvx --from "git+https://github.com/YordiLorenzo/oriel#subdirectory=vnc" oriel-vnc

Needs uv. List your machines in the host file; logins can come from an environment variable or a command. Set-up and tools.

To check it without a client: & "$env:LOCALAPPDATA\Programs\oriel\oriel.exe" call windows. To update, run install from the new oriel.exe. Everything oriel changes on your PC, and how to undo it, is in What oriel changes on your PC. Smart App Control, if it is on, blocks unsigned programs; you can build oriel yourself instead.

Frequently asked questions

Anything else? The README has more answers, and you can always open an issue.

How does it compare with Cua Driver and screenshot-based agents?

Screenshot-based agents read pictures of the screen and click at pixel positions. Cua Driver reads the accessibility tree as text too, with screenshots on request, and reads the window again to see what an action changed. oriel lists what changed in the same reply, element by element. In WindowsAgentArena round 9, with the same model, a task took a median of 49 s with oriel and 70 s with Cua Driver, and all 153 tasks cost $38 against $61. Cua Driver completed 4 points more tasks: 67% against 63%. The benchmarks have every round.

Is it safe to let an assistant use my PC?

Treat it like someone using your PC on your behalf: in the windows it is allowed to touch, it can do what you can. Keys, clicks and drags go only to a window that is verified to be in front, and wait for a pause in your own typing and mouse use. Nothing is typed into a password field, and text may only come before a key that can move focus, so {TAB}secret is refused. An allow-list in config.json keeps it to the apps you name. SECURITY.md lists what oriel guarantees and what it doesn't.

oriel.exe isn't code-signed. Can I trust it?

Windows warns about 0.1.0 because it isn't signed yet. The source is open, every release lists the file's hash in SHA256SUMS, and you can build oriel yourself with the C# compiler that ships with Windows. Code signing is first on the roadmap: the plan is to apply to the SignPath Foundation. oriel doesn't try to get around antivirus.

Can I keep using the PC while the assistant works?

For reading and element actions, yes: invoke, set, select and scroll don't take keyboard focus or move the mouse. keys, click, drag and focus bring a window to the front, so they interrupt you. They wait for a pause in your typing and mouse use, and are refused if you keep going.

Which MCP clients does it work with?

Any client that starts a stdio MCP server. Most of the testing used Claude Code. The configs on this page for Codex, Claude Desktop, Cursor and VS Code follow each client's documented format but aren't tested yet.

Does it work on a Mac or on Linux?

oriel.exe runs on Windows only. From a Mac or a Linux machine, your assistant can use a Windows PC over SSH. To operate the Mac or Linux machine itself, use oriel-vnc, the second MCP server in the repo: it works with any desktop that runs a VNC server, through screenshots, clicks and keys.

What can't it do?

Canvases and games have no accessibility tree, so oriel can only look at them with screenshot and act with click and drag. Apps running as administrator are out of reach unless oriel runs elevated too; don't run it elevated without a reason. On a locked PC, keys, clicks, drags and bringing a window to the front are refused. It has no shell or file tools by default.

What does it change on my PC?

It needs no admin rights and installs for your Windows account only, with no service or driver. oriel install copies the exe to %LOCALAPPDATA%\Programs\oriel. The first time it runs, it makes %LOCALAPPDATA%\oriel for its per-user key and settings. --autostart adds a logon entry under HKCU\...\Run. When a client connects over SSH and the daemon isn't running, a one-time scheduled task starts it and is then deleted. While the daemon runs, it listens on 127.0.0.1 on a port of its own. The full list says how to undo each one.

Does it send anything anywhere?

No. oriel makes no network connections other than between its own processes on 127.0.0.1: no telemetry, no update checks. Your MCP client does send what oriel reads (window titles, control names, the text you ask it to read) to its model provider, as it does with anything else you show it.

How do I remove it?

In PowerShell:

& "$env:LOCALAPPDATA\Programs\oriel\oriel.exe" uninstall

This stops the daemon, removes the logon entry if there is one, deletes the install folder and the settings folder, and lists what it removed. Then remove oriel from your MCP client's config.
