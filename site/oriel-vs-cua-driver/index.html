oriel and Cua Driver compared

Both are MCP servers that read the Windows accessibility tree. On WindowsAgentArena round 10 (13 Nov 2026), with the same model, tasks took a median 49 s with oriel 0.1.3 and 68 s with Cua Driver 0.46.1, at 56% lower model cost. Cua Driver, without 4 of its 63 tools, completed 75% of tasks and oriel 73%. That gap is too small for one run to show a difference, but Cua Driver completed more in every round since round 5. If completion is what you need most, Cua Driver is a fair choice.

Whole tasks: WindowsAgentArena round 10

WindowsAgentArena is Microsoft's benchmark of everyday tasks in a Windows 11 VM, scored by its own scripts. Both layers ran Claude Sonnet 5.5 in Claude Code, with the same prompt and a 50-turn limit; the prompt differs in one sentence, which names the layer's tools. Round 10 ran oriel 0.1.3 against Cua Driver 0.46.1 on 13 Nov 2026. Only run 1 counts, on the 151 tasks that both layers scored.

What round 10 shows, and what it doesn't

  • Time, cost and turns. With oriel, the median time was 29% lower, the model cost 56% lower and there were 13% fewer turns. The 95% intervals run from 14% to 42% lower for time, 53% to 60% lower for cost and 5% to 19% fewer turns, so none of them reaches zero.
  • Not only failing sooner. On the 102 tasks that both layers completed, oriel took a median 39 s against 62 s, with 26.7 against 32.0 turns.
  • Completion. Cua Driver completed 2.9 tasks more (1.9 points). The 95% interval of that gap runs from 7.0 points in Cua Driver's favour to 3.3 in oriel's, so it reaches zero: round 10 shows no completion difference. oriel completed more on the held-out half and in LibreOffice Writer; Cua Driver completed more on the dev half (64 against 59) and in Edge (10 against 7 of 13).
  • One run. In run 2 the model API refused most calls of both layers (429, rate limit), so it is left out. The intervals cover which tasks are in the benchmark, not the variation between two runs of the same set-up. In round 9 that variation moved Cua Driver's completion by 6.5 points.
  • Set-up. Round 10 ran on a Linux PC instead of a cloud server, with a new Windows image, effort xhigh, and only ToolSearch of Claude Code's own tools. Both layers completed more tasks and took more turns than in round 9, so compare the two layers within a round, not across rounds.
  • Version. 0.46.1 was the newest Cua Driver on 10 Nov 2026. The newest on 17 Nov 2026 is 0.53.0, which no round has run.

What round 9 shows, and what it doesn't

  • Time, cost and turns. With oriel, the median time was 30% lower, the model cost 38% lower and there were 19% fewer turns. Each gap is larger than the gap between either layer's own two runs. Swapping the server did this; the benchmark does not show which feature did it.
  • Not only failing sooner. On the 77 tasks that all four runs completed, oriel took a median 46 s against 63 s, with 17.8 against 23.7 turns.
  • Completion. Cua Driver completed 4.2 points more (67% against 63%). Its own two identical runs differed by 6.5 points, so that gap is within run-to-run variation. But its lower run (98) still beat oriel's higher run (97), and it completed more in every round since round 5. Most of the gap is LibreOffice Writer.
  • Version. Round 9 ran Cua Driver 0.38.0, released 21 Oct 2026.

Both rounds

  • Earlier rounds. The time gap appeared in round 8. In rounds 1 to 7, oriel's median time was the same as Cua Driver's or longer. oriel's model cost was about a third lower in rounds 1 to 9, and 56% lower in round 10.
  • Hidden tools. Cua Driver ran without 4 of its 63 tools. run_script runs JavaScript over Cua Driver's own tools in a sandbox with no file, network or process access; it is on by default. It was hidden because oriel has no script tool, and with it Cua Driver might need fewer turns, less time and less cost. install_ffmpeg and install_extension install software, and check_for_update checks GitHub for a newer driver. Cua Driver with run_script was not measured.
  • Cost is the model cost Claude Code reported for each task, a list-price estimate from the token counts, not a bill. Both layers are priced with the same table.

Per call: 10 Nov 2026, Cua Driver 0.46.1

The same tasks through both servers on one unlocked Windows 11 PC, driven from a MacBook on the LAN. oriel 0.1.0 against Cua Driver 0.46.1, the newest release that day, through its daemon. 5 runs per task, median wall time per MCP call.

  • To read a window, Cua Driver first lists windows to find it: 30 ms more.
  • Cua Driver 0.38.0, run the same day, was within 15 ms of 0.46.1 on every row. The larger gaps measured on 21 Oct 2026 came from that day's conditions, most likely the locked PC. That is an inference: the open windows differed too.
  • Bare cua-driver mcp shows its agent cursor by default, which adds about 565 ms to each fill and press. With the cursor off it matches the daemon within 2 ms.

Which to choose

  • Cua Driver if completion is what you need most, or if you want a script tool in the server.
  • oriel if you want each task done in less time, at lower model cost and in fewer turns, the change in the same reply, and one exe under 200 KB with no admin rights, which keeps password fields, sign-in, UAC prompts, password managers and terminals off limits by default.

Not tested

  • No WindowsAgentArena round has run Cua Driver 0.53.0, the newest on 17 Nov 2026, or Cua Driver with run_script.
  • One model (Claude Sonnet 5.5 in Claude Code), one prompt, and VMs on one host per round: a cloud server with nested VMs in round 9, a Linux PC in round 10. Not other models, other clients or real hardware.
  • The per-call numbers come from one Windows 11 PC.
  • oriel is tested with Claude Code on Windows 11 only.

Questions

Did you test an old Cua Driver?

WindowsAgentArena round 10 (13 Nov 2026) ran Cua Driver 0.46.1, the newest release on 10 Nov 2026. Round 9 (October 2026) ran 0.38.0. The per-call run of 10 Nov 2026 used 0.46.1 too: oriel took less time on every call, and 0.38.0, run the same day, was within 15 ms of 0.46.1. The newest Cua Driver on 17 Nov 2026 is 0.53.0, which no round has run.

Why was run_script hidden?

oriel has no script tool, so scripting was kept out of the comparison. run_script runs JavaScript over Cua Driver's own tools in a sandbox with no file, network or process access. It is not a shell. Cua Driver with run_script was not measured.

Is Cua Driver's completion lead real?

In round 10, Cua Driver 0.46.1 completed 1.9 points more (75% against 73%). The 95% interval of that gap runs from 7.0 points in Cua Driver's favour to 3.3 in oriel's, so the round shows no completion difference. In round 9, Cua Driver 0.38.0 completed 4.2 points more (67% against 63%), and its own two identical runs differed by 6.5 points. But Cua Driver completed more in every round since round 5.
